# Security Policy

## Reporting

Please do not publish security vulnerabilities as public issues.

For now, open a minimal GitHub issue stating that you have a security concern
without including exploit details or sensitive information. A private reporting
channel can be added when the project is production-ready.

## Scope

Security-sensitive areas include:

- capability and package validation
- dependency / SBOM handling
- rights and provenance metadata
- API authentication
- marketplace packaging
- agent authorization
- payment / procurement integrations
- release hashes and receipts

## Disclosure

Do not include credentials, private keys, access tokens, customer data or trade
secrets in issues, pull requests or repository history.
